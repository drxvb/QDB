# Benchmarks: method and results

All numbers come from `crates/quickdb-bench` (one generic harness, `run<S: Store>`, identical operations for every
backend) or the `qbench` example of each backend crate. Runs used x86_64 Linux, Rust 1.91.1, in containers capped at the
stated CPU count, on shared hosts. Every row says how many runs it rests on; treat "single run" as indicative only.
Rerun them on your own hardware before relying on a number.

## Datasets

| Dataset | Shape | Source |
|---|---|---|
| SIFT-1M | 1,000,000 × 128, L2, published ground truth | http://corpus-texmex.irisa.fr/ |
| GIST-1M | 1,000,000 × 960, L2, published ground truth | http://corpus-texmex.irisa.fr/ |
| Research corpus | 22,666 chunks × 1,024 (BGE-M3 embeddings), 1,195 documents, Arabic and English | private, not shipped |
| Synthetic | seeded clusters, `--rows`/`--dim` of your choice | generated by `qbench synthetic` |

Queries: for SIFT and GIST, the published query vectors and truth; for the corpus and synthetic sets, 200 held-out vectors
with deterministic perturbations, scored against an exact brute-force top-10. Recall@10 is the mean per-query
intersection divided by `min(10, eligible vectors)`, ties broken by id.

## Commands

```sh
cargo run --release -p quickdb-native --example qbench -- ann --backend native \
  --base sift_base.fvecs --query sift_query.fvecs --truth sift_groundtruth.ivecs \
  --limit 1000000 --queries 10000 --metric l2 --data-dir ./run-sift --out ./sift.json
cargo run --release -p quickdb-native --example qbench -- synthetic --backend native \
  --rows 100000 --dim 1024 --data-dir ./run-syn --out ./syn.json
cd crates/quickdb-vec1 && cargo run --release --example qbench -- ann --backend vec1 ...   # same flags per adapter
```

The data directory must be missing or empty. The JSON report holds phase timings, sizes, memory snapshots and
p50/p95/p99 per query family; the schema is in `crates/quickdb-bench/README.md`.

## Paired timing method (A/B of two builds)

For small speed differences between two versions, single runs are noise. The harness's `ab` mode measures query latency
only (GIST first 30,000 vectors, 1,000 queries, L2, ef 64) on one deterministic graph that both arms reopen:

- warm every query once after each open, then measure all 1,000 queries;
- alternate AB and BA order, 20 adjacent pairs per trial, three A/A trials and one A/B;
- the ratio is median(A block medians) / median(B block medians); resample adjacent pairs together 10,000 times and
  report the 95% interval; blocks, not queries, are the units;
- stable only if the interval is within 1.10 and recall, result-distance fingerprint and distance counts agree across arms;
  an A/A control must land in [0.95, 1.05];
- pin the query thread to one CPU, record load average before and after every block, never drop outliers.

`QUICKDB_DISTANCE_COUNTER=1` at compile time enables a thread-local distance counter (compiled away otherwise); instrumented
times are not production latencies.
